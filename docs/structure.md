# 프로젝트 구조와 기능 — 비전공자용 설명서

> 이 문서는 "오늘의 진짜 정보판"이 무엇이고, 어떻게 돌아가며, 파일들이 각각 무슨 일을 하는지 **IT 배경지식이 없는 사람도 이해할 수 있게** 풀어 쓴 안내서입니다.

---

## 1. 이 프로젝트가 하는 일 (한 문단 요약)

매일 **Hacker News**라는 IT 뉴스 게시판에 올라오는 글 제목들을 모아서, **가장 많이 등장한 단어 5개**를 뽑아 보여줍니다. 그리고 그 결과를 **날짜별로 저장**해두었다가, 다음 날이 되면 **어제와 비교해서 얼마나 늘었는지/줄었는지** 알려줍니다. 만약 뉴스 데이터를 못 가져오는 상황(인터넷 끊김, 서버 오류 등)이 생기면, **마지막으로 성공했던 값을 지우지 않고 그대로 보여주면서 "이건 좀 오래된 값이에요"라고 정직하게 표시**합니다.

---

## 2. Hacker News가 뭔가요?

**Reddit이나 클리앙의 IT 버전**이라고 생각하시면 됩니다. 전 세계 개발자들이 "오늘 이런 기술 뉴스가 떴다"라고 링크를 올리고, 다른 사람들이 투표(추천)하는 게시판입니다. 구글의 투자회사인 Y Combinator가 운영합니다.

- 사람들이 올린 글 하나하나를 **"스토리(story)"** 라고 부릅니다.
- 각 스토리에는 **제목**, **올린 시각**, **추천 수**, **댓글**이 있습니다.
- 우리는 이 중에서 **제목**만 가져다가 단어 빈도를 셉니다.

**비유**: 도서관에 하루 동안 새로 들어온 책 제목들을 모아서, "오늘은 'AI'라는 단어가 들어간 책이 제일 많았네"라고 세는 것과 비슷합니다.

---

## 3. "Top 5 키워드"가 뭔가요?

하루치 스토리 제목들을 전부 모아서, **가장 자주 나온 단어 5개**를 뽑은 것입니다.

### 예시

오늘 스토리 제목이 이렇다고 해봅시다:

1. "OpenAI releases new AI model"
2. "Why AI agents are the future"
3. "The AI bubble debate"
4. "Rust vs Go in 2026"
5. "New security flaw found"

여기서 "the", "in", "are" 같은 흔한 단어(불용어)를 빼고 세면:

- **ai**: 3번 (1, 2, 3번 제목)
- **model**: 1번
- **agents**: 1번
- **bubble**: 1번
- **rust**: 1번
- ...

이걸 **많이 나온 순서로 정렬**해서 상위 5개를 뽑습니다. 이게 "Top 5 키워드"입니다.

### "주 값"이 뭔가요?

Top 5 중 **1등 키워드의 등장 횟수**를 "주 값"이라고 부릅니다. 위 예시에서는 `ai`가 3번 나왔으니 주 값은 **3건 (ai)** 입니다.

이 프로젝트에서는 **매일 이 주 값 하나를 기록**합니다. 나머지 Top 2~5는 "보조 값"으로 함께 보여줍니다.

---

## 4. "어제 대비 변화"는 어떻게 계산하나요?

**오늘 주 값 − 어제 주 값** 입니다.

### 예시

| 날짜 | 1위 키워드 | 주 값 |
|---|---|---|
| 2026-09-14 | ai | 78건 |
| 2026-09-15 | ai | 85건 |

→ 어제 대비 변화: **+7건**

만약 1위 키워드가 바뀌었다면:

| 날짜 | 1위 키워드 | 주 값 |
|---|---|---|
| 2026-09-14 | ai | 78건 |
| 2026-09-15 | rust | 92건 |

→ 어제 대비 변화: **+14건**, 그리고 **1위 키워드가 ai에서 rust로 바뀌었다**는 표시가 뜹니다.

---

## 5. "데이터가 안 올 때" 어떻게 하나요?

이 프로젝트의 **핵심 목적**입니다. 뉴스를 못 가져오는 상황은 여러 가지가 있습니다:

| 상황 | 무슨 일이 생긴 건가요 | 정보판이 보여주는 것 |
|---|---|---|
| **느린 응답** | 서버가 너무 늦게 답함 | "느린 응답" 상태 + 마지막 정상값 |
| **401/403 거절** | 서버가 "너는 접근 권한 없어"라고 거절 | "401/403 거절" 상태 + 마지막 정상값 |
| **호출 제한** | "너 너무 많이 요청했어, 좀 기다려" | "호출 제한" 상태 + 마지막 정상값 |
| **오프라인** | 인터넷이 끊김 | "오프라인" 상태 + 마지막 정상값 |
| **형식 변경** | 서버가 갑자기 다른 형식으로 답함 | "형식 변경" 상태 + 마지막 정상값 |

**중요한 원칙**: 어떤 실패가 나든, **마지막으로 성공했던 값을 지우지 않습니다.** 대신 그 값에 **"오래된 값"** 이라는 표시를 붙여서, "이건 지금 값이 아니라 예전 값이에요"라고 정직하게 알려줍니다. 그리고 **"다시 시도"** 버튼을 보여줍니다.

이게 이 과제의 핵심 철학입니다: **"데이터가 없다고 거짓말하지도, 없다고 화면을 비우지도 않는다. 정직하게 현재 상태를 설명한다."**

## 7. 실제로 어떻게 돌아가나요? (하루의 흐름)

### 아침: 개발자가 명령어를 실행
npm run fetch:daily


이 명령어가 하는 일:
1. "한국 시간으로 오늘이 며칠이지?"를 계산
2. Hacker News에 "오늘 하루 동안 올라온 스토리 전부 보여줘"라고 요청
3. 받아온 제목들에서 단어 빈도를 세서 Top 5를 뽑음
4. 결과를 `public/data/오늘날짜.json` 파일로 저장
5. `public/data/index.json`에 "오늘 파일이 추가됐어"라고 기록

### 심사자가 웹사이트를 열면

1. 브라우저가 `public/data/index.json`을 읽어서 "어떤 날짜 기록이 있지?"를 확인
2. 각 날짜의 JSON 파일을 읽어옴
3. 화면에 표시:
   - 가장 최근 날짜의 주 값과 Top 5
   - 출처, 출처 시각, 조회 시각, 기준 시간대
   - 어제와 비교한 변화
4. 만약 마지막 기록이 오늘 날짜가 아니면 → "오래된 값" 배지 표시

### 심사자가 "복구 재생" 버튼을 누르면

1. `public/fixtures/T04-RECOVER-D2` 파일을 읽어옴
2. 그 안에 적힌 합성값(예: ai 12건)으로 **"2026-09-15"라는 가상의 날짜 기록**을 하나 추가
3. 상태가 "정상"으로 돌아오고, 일별 기록이 1건 늘어남

## 8. "정직하다"는 게 무슨 뜻인가요?

이 프로젝트에서 "정직"은 세 가지를 뜻합니다.

### ① 값을 지어내지 않는다
데이터를 못 가져오면, **절대로 그럴듯한 가짜 값을 만들어내지 않습니다.** 마지막 정상값을 그대로 보여주되, "이건 오래된 값"이라고 표시합니다.

### ② 현재 상태를 숨기지 않는다
"인터넷이 끊겼어요", "서버가 거절했어요", "응답이 너무 느려요"처럼 **무슨 일이 생긴 건지 구체적으로** 알려줍니다. 그냥 "오류"라고 뭉뚱그리지 않습니다.

### ③ 다음에 뭘 해야 하는지 알려준다
"네트워크 연결을 확인한 뒤 다시 시도하세요"처럼 **사용자가 다음에 취할 행동**을 안내합니다.

## 9. 자주 나오는 용어 정리

| 용어 | 뜻 |
|---|---|
| **KST** | 한국 표준시 (Korea Standard Time). UTC+9. |
| **UTC** | 세계 표준시. 한국은 UTC보다 9시간 빠름. |
| **RFC 3339** | 날짜·시각을 표기하는 국제 표준 형식. 예: `2026-09-14T13:11:41+09:00` |
| **SHA-256** | 파일의 "지문". 파일 내용이 1바이트라도 바뀌면 완전히 다른 값이 나옴. 무결성 검증에 씀. |
| **fixture** | "시험용 고정 데이터". 실제 데이터 대신 넣어두는 가짜 값. |
| **합성(synthetic)** | "인위적으로 만든"이라는 뜻. 실제 데이터가 아님을 명시. |
| **stale** | "오래된". 마지막 정상값이 현재 날짜 것이 아닐 때. |
| **CORS** | 브라우저가 다른 사이트의 데이터를 가져올 수 있게 해주는 규칙. |
| **API** | 프로그램끼리 대화하는 창구. |
| **배포(deploy)** | 만든 웹사이트를 인터넷에 올려서 누구나 볼 수 있게 하는 것. |
| **Vercel** | 웹사이트를 무료로 인터넷에 올려주는 서비스. |
| **commit / push** | 코드의 변경 사항을 저장하고, GitHub에 올리는 것. |

## 10. 한눈에 보는 전체 그림
[심사자] ──웹브라우저──> [Vercel에 배포된 정보판]
│
├── public/data/ 에서 저장된 기록 읽음
├── public/fixtures/ 에서 실패 시험값 읽음
└── (선택) Hacker News에 직접 조회

[개발자] ──npm run fetch:daily──> [Hacker News Algolia API]
│
└── 결과를 public/data/에 저장


**핵심**: 정보판은 **저장된 기록을 읽어서 보여주는 것**이 기본이고, **"지금 조회" 버튼을 누르면 실시간으로 Hacker News에 물어볼 수도 있습니다.**

---

## 11. 이 프로젝트가 지키는 약속

- ✅ **비밀키를 쓰지 않습니다** — Hacker News API는 키가 필요 없습니다.
- ✅ **개인정보를 수집하지 않습니다** — 로그인도, 추적도 없습니다.
- ✅ **실패를 숨기지 않습니다** — 실패하면 실패했다고 정직하게 말합니다.
- ✅ **마지막 정상값을 지우지 않습니다** — 데이터가 없어도 화면이 비지 않습니다.
- ✅ **합성값과 실제값을 구분합니다** — 시험용 값에는 "합성"이라고 표시합니다.
